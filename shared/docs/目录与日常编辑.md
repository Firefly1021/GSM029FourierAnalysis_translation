# 一个总目录, 两个日常区域

本次目录整合由用户于 2026-10-22 明确要求. 它取代原先“主仓库 + 外部书籍 worktrees”的日常使用方式, 不改变任何书籍的翻译内容、数学表达或模板视觉设计.

```text
BOOKTRANSLATION/
├── books/
│   ├── fourier-analysis/

│   ├── navier-stokes-equations-theory-and-numerical-analysis/
```

隐藏的 Git 元数据仍位于总目录. 日常不需要进入它.

## 我想修改一本书

用 VS Code 打开 `books/<book-id>/`, 先看 `OPEN-THIS-BOOK.md`. 每本书的正式入口已明确登记, 不应仅凭文件名猜测哪个 `main.tex` 是全书入口. 尤其扫描版 Navier--Stokes 有限元书的旧 `tex/main.tex` 是样本, 本次把原全书入口逐字节固定为 `tex/full-book.tex`; 两者没有混为一谈.

每本书均集中保留:

- `input/source/`: 原始 PDF, 只读.
- `template/`: 从该书原工作区复制的完整模板快照, 包括适配文件和依赖资源. 不自动升级到共享最新版.
- `tex/`: 主入口、章节、图片及构建所需宏文件. 不为整理目录而重写章节.
- `structured/`、`translation/`、`formulae/`: 英文恢复稿、译文与数学登记.
- `glossary/`: 本书姓名、记号、术语候选及未决项; 不取代共享术语库.
- `workspace/crops/`: 保留的原页定位裁剪证据. 全页衍生图、OCR 临时结果、构建缓存及过程日志已清理.
- `qa/`: 既有文字验收记录、公式/引用登记、问题和扫描诊断. 旧记录中的缓存路径不表示缓存仍应存在.
- `output/`: 正式 PDF. 样本、章节预览和重复的累计输出已清理; FEEC 另保留已有 Mystyle 正式版, 不和 AJbook 正式版混淆.

本次参考了用户“数学基础”目录中主入口、章节和图片集中管理的优点. 没有搬入它的内容或模板, 也没有为了表面整齐而破坏既有的 TeX 相对路径.

## 我想在一个窗口查看全部项目

打开 `shared/BOOKTRANSLATION.code-workspace`. 它在同一 VS Code 窗口列出七本书和共享项目. 也可直接打开整个 `BOOKTRANSLATION` 总目录.

共享规则和唯一权威全局术语库分别在 `shared/AGENTS.md`、`shared/glossary/terminology.tsv`. FEEC 的 AJbook 与原 Mystyle 分开保存, 没有合并成一套视觉样式.

## 编译

在一本书的 VS Code 窗口运行“编译本书”任务, 或在总目录运行:

```powershell
.\shared\scripts\mathbook.ps1 build-book finite-element-exterior-calculus
```

编译读取该书登记的入口及书内模板快照, 并写入新的书内临时构建目录. 不自动覆盖已验收正式 PDF. 需要发布修改后的正式 PDF 时, 仍须重新检查对应公式、引用、姓名、标点和排版.

共享启动器会读取不提交的 `shared/config/runtime.local.json` 或寻找可用 Python, 避免误启动 Windows 应用商店的空壳命令. 在别的电脑仍须具备 Python 依赖和 TeX Live.

## Git 提交和远端

总目录是唯一的日常 Git 仓库. 日常修改在 `main` 的统一工作目录内进行, 按书籍路径检查和提交. 不再切换到历史 `book/` 分支编辑, 也不在它们的旧工作区提交. 系统维护仍使用独立维护分支.

推送不是编译或翻译程序的一部分. 本次整合不自动推送, 不改变远端地址, 不改写历史.

## 历史与恢复

旧工作区的分支、提交和注册保留在 `shared/.legacy-worktrees/`, 已锁定并使用只显示少量根说明文件的稀疏视图. 不再保存完整的重复书籍目录和缓存. 扫描书原有未提交 `uv.lock` 仍保留在对应历史工作区. 冗余迁移副本已清理; 原主目录独有的六份文件已逐字节移存到 Fourier 书内 `archive/pre-integration-main/`.

已跟踪的旧过程脚本和阶段文件可从本地提交 `538012e` 或对应原书分支恢复. 被删除的未跟踪衍生图像、OCR 和编译缓存须由保留的原始 PDF 重建, 没有声称这些缓存有完整备份. 不改写 Git 历史.

历史 QA、日志和原配置中的旧绝对路径保持原字节不变, 便于审计. 当前路径以书内 `config/library-binding.json` 和 `shared/PROJECTS.md` 为准. 模板快照实际哈希与历史配置值分别记录, 不静默改写旧哈希来制造一致.

`template-accepted/` 只在两本旧书中存在: 原样保存经原验收清单 SHA-256 验证的历史模板, 用于可重复编译. 后来更新的用户模板仍在 `template/`, 完全没有改写. 新目录绑定明确记录使用哪一版, 不悄悄混用.

迁移清单在 `shared/qa/integration-20261022/`: 包含原位置、分支头、复制文件的路径/大小/SHA-256、逐书模板快照清单及最终核验. 同盘直接搬迁的被忽略缓存另以原文件标识、大小和时间戳逐项核验, 不把它们谎称为逐项重新计算过内容哈希. 这些证明目录搬迁的完整性, 不把旧译本重新宣称为已通过新的数学验收.

`verification.json` 是清理前的完整迁移验收记录, 不代表缓存清理后这些文件仍存在. 后续保留清单、实际删除回执和清理后验收另行记录. 不通过重跑旧迁移清单来要求恢复本来就应删除的缓存.
